# AutoSkip（自动跳过）

AutoSkip 是一款基于 [Shizuku](https://github.com/RikkaApps/Shizuku) 和 Android `UiAutomation` 的启动广告自动跳过工具。它在广告界面出现后识别“跳过”类控件并执行点击，无需开启系统无障碍服务，也不依赖常驻通知。

[下载最新版](https://github.com/ybs15090/AutoSkip/releases) · [使用教程](#使用教程) · [识别规则](#识别规则详解) · [工作原理](#工作原理) · [自行构建](#自行构建)

> [!IMPORTANT]
> AutoSkip 是界面自动化工具，不是网络广告过滤器。它不会拦截广告请求，只能处理已经显示且能被 Android 界面系统读取的控件。网页画布、视频画面、系统安全窗口或未暴露界面元素的广告可能无法识别。

## 功能概览

- **无需无障碍服务**：通过 Shizuku 启动特权进程，并使用 Android `UiAutomation` 监听界面和执行动作。
- **清晰的首次使用流程**：依次检查 Shizuku 安装、运行、授权、AutoSkip 服务和开机自动恢复状态。
- **应用白名单与黑名单**：支持总开关、普通模式、严格模式和每个应用的独立开关，不预置默认应用名单。
- **可配置识别规则**：可按文字、内容描述、View ID、控件类型，以及精确、包含、正则等方式匹配。
- **全局规则与应用专属规则**：每个应用都能独立配置关键词、区域、延迟和点击方式；专属规则可暂时停用而不被删除。
- **全屏及分区识别**：支持全屏、上下半屏、左右半屏和四角区域；内置默认规则使用全屏范围。
- **候选控件评分**：多个控件同时匹配时，综合匹配精度、位置、大小和可点击性选择最可信的候选。
- **规则学习模式**：采集目标应用当前界面的候选控件，选择真正的跳过按钮后自动生成专属规则。
- **有限点击重试**：点击后重新确认页面状态，仅在候选仍存在时按间隔重试，避免一次注入成功却未真正触发。
- **误触快速处理**：首页可将最近一次误触对应的应用一键加入黑名单，并支持立即撤销。
- **本地统计与记录管理**：查看跳过次数和时间，支持排序、删除单个应用记录和清空全部记录。
- **开机自动恢复**：在 Shizuku 运行条件满足时，可在设备启动后恢复 AutoSkip 服务。

## 使用前准备

### 系统要求

- Android 6.0（API 23）或更高版本。
- 已安装并正在运行的 Shizuku；Root 设备也可使用 Sui 环境。
- 已在 Shizuku 中授予 AutoSkip 权限。

Shizuku 的启动方式取决于 Android 版本和设备状态：Root 设备可直接启动；Android 11 及以上的非 Root 设备通常可使用无线调试；其他情况可连接电脑通过 ADB 启动。具体步骤请以 [Shizuku 官方使用指南](https://shizuku.rikka.app/guide/setup/) 和 Shizuku 应用内提示为准。

> [!NOTE]
> 受 Android 系统限制，使用无线调试或电脑启动的 Shizuku 通常需要在设备重启后重新启动。AutoSkip 的“开机自动恢复”不能替代 Shizuku 本身的启动条件。

### 下载与安装

1. 从本仓库的 [Releases 页面](https://github.com/ybs15090/AutoSkip/releases) 下载 APK。
2. 在手机上正常安装或覆盖更新 AutoSkip。
3. 安装并启动 Shizuku，然后回到 AutoSkip 完成首次使用检查。

请只从可信来源下载 APK。不同签名的安装包通常不能直接覆盖安装，升级前请确认安装包来源一致。

## 使用教程

### 1. 完成首次使用检查

首次打开 AutoSkip 后，按页面顺序完成以下五项：

1. **已安装 Shizuku**：若未安装，点击“安装”并按提示获取 Shizuku。
2. **Shizuku 正在运行**：点击“启动”进入 Shizuku，根据设备情况完成 Root、无线调试或 ADB 启动。
3. **已授予 AutoSkip 权限**：点击“授予 Shizuku 权限”，在授权对话框中允许 AutoSkip。
4. **AutoSkip 服务正在运行**：点击“启动自动跳过”。
5. **开机自动恢复**：点击“开启”；若环境异常，按页面上的“修复”操作。

全部完成后，应用会进入简洁的日常主页。之后可在首页直接“启动自动跳过”或“停止自动跳过”，运行卡片会显示本次持续时间和开机自动恢复状态。

### 2. 选择 AutoSkip 生效的应用

进入首页的“应用范围”。应用范围只决定 AutoSkip **在哪些应用中工作**，不改变具体识别关键词。

| 设置组合 | 实际效果 | 适用场景 |
| --- | --- | --- |
| 关闭“应用范围控制” | 忽略白名单和黑名单，对所有可识别应用生效 | 希望全局启用，且能接受较高误触风险 |
| 开启控制，关闭“严格模式” | 普通模式：默认对应用生效；关闭某个应用即加入黑名单 | 只想排除少数应用 |
| 开启控制，同时开启“严格模式” | 仅对手动开启的应用生效 | 推荐的安全起步方式 |

页面支持按应用名称或包名搜索。每个应用右侧有两个入口：

- **应用开关**：允许或禁止 AutoSkip 在该应用内执行动作。
- **识别规则**：打开该应用的专属规则与学习模式。

“单次点击限制”默认关闭。开启后，每次进入一个应用最多自动点击一次；如果同一应用内可能连续出现多个需要处理的页面，请保持关闭。

### 3. 使用全局识别规则

在“应用范围”页面点击“全局识别规则”。初始规则会在全屏范围内匹配以下内容：

- 控件文字包含“跳过”；
- 控件文字包含“skip”，忽略大小写；
- 控件内容描述包含“跳过”；
- 控件内容描述包含“skip”，忽略大小写。

可以启用、停用、编辑或删除任意规则，也可点击“恢复默认”重新载入内置规则。

全局规则适合通用的“跳过”“关闭广告”“略过”“Skip Ad”等文案。若某个关键词可能在普通页面中出现，建议结合更精确的匹配方式、区域限制或严格模式降低误触风险。

### 4. 为单个应用配置专属规则

在“应用范围”中找到目标应用，点击其“识别规则”：

1. 点击“新增规则”。
2. 选择识别特征和匹配方式。
3. 输入关键词、View ID、控件类型或正则表达式。
4. 选择控件区域、点击方式和延迟时间。
5. 保存规则并确认其开关已开启。

只要某个应用存在且启用了专属规则，该应用就会使用专属规则替代全局规则。点击“改用全局规则”只会停用并保留原有专属规则；以后点击“启用专属规则”即可恢复，无需重新配置。

### 5. 使用规则学习模式

当广告按钮文字特殊、倒计时不断变化，或无法确定 View ID 时，可让 AutoSkip 采集候选控件：

1. 先确认 AutoSkip 服务正在运行。
2. 进入“应用范围”，找到目标应用并打开“识别规则”。
3. 点击“学习模式”→“开始采集”，AutoSkip 会打开目标应用。
4. 在目标应用中进入广告页面，等待真正的跳过按钮出现。
5. 通过最近任务返回 AutoSkip。
6. 在候选列表中选择真正的跳过按钮。
7. 检查自动生成的特征、表达式、区域和点击方式，确认后保存。

候选列表会显示采集到的文字、内容描述或 View ID，以及位置、可点击状态和评分。若按钮文字包含变化的数字，例如“5 秒后跳过”，学习模式会尝试把数字部分泛化为正则表达式。

> [!TIP]
> 学习模式生成的是建议规则，不是不可修改的结果。保存前应尽量选择稳定的 View ID 或明确文字，并把区域缩小到按钮实际出现的位置。

### 6. 查看动作、处理误触和管理记录

- 首页“最近动作”会显示最近一次成功确认的应用、时间和控件文字。
- 如果发生误触，点击“误触，加入黑名单”；操作后可通过底部提示立即撤销。
- 点击首页“统计数据”查看各应用的累计次数、首次及最近跳过时间，并按名称、次数、频率或时间排序。
- 在单个应用的记录详情中可删除该应用记录。
- 在统计页面右上角菜单中可清空全部记录；此操作无法撤销。

### 7. 测试与故障信息

首页右上角“更多”菜单还提供：

- **可用性测试**：在服务运行时验证目标识别和模拟点击是否可用。
- **开机自动恢复**：随时开启或关闭自动恢复。
- **导出日志**：出现异常时导出日志用于排查。
- **反馈**：通过邮件或 GitHub Issues 报告问题。
- **工作原理**：在应用内查看识别、评分和动作执行说明。
- **关于**：查看版本、开源许可、捐赠和最新版下载入口。

## 识别规则详解

### 规则字段

| 字段 | 可选项 | 说明 |
| --- | --- | --- |
| 识别特征 | 文本、内容描述、View ID、控件类型 | 分别对应控件的 `text`、`contentDescription`、资源 ID 和类名 |
| 匹配方式 | 精确、包含、正则 | 精确匹配最稳妥；包含匹配适合带倒计时的文字；正则最灵活，但需注意误匹配 |
| 忽略大小写 | 开/关 | 主要影响英文字母，例如同时匹配 `Skip` 和 `SKIP` |
| 控件区域 | 任意区域、上下半屏、左右半屏、四角 | “任意区域”即全屏；限制区域可显著减少同名控件误触 |
| 延迟 | 0～15000 ms | 匹配后等待指定时间，再重新确认并尝试点击 |
| 点击方式 | 自动、仅控件点击、仅坐标点击 | 自动模式优先控件点击，失败时回退到坐标点击 |

### 如何选择匹配方式

- 按钮始终显示固定文字，例如“关闭广告”：优先使用**精确匹配**。
- 按钮包含额外内容，例如“跳过 3”：可使用**包含匹配**“跳过”。
- 倒计时形式变化，例如“5 秒后关闭”“4 秒后关闭”：可使用**正则匹配**，例如 `\d+\s*秒后关闭`。
- 文字为空但控件有稳定资源 ID：使用 **View ID**，通常比宽泛文字更可靠。
- 只有通用控件类型可用：应同时收紧区域和应用范围，因为单独匹配控件类型容易误触。

正则规则使用 Kotlin/Java 正则语法。无效表达式无法保存；过于宽泛的表达式即使合法，也可能匹配普通页面元素。

### 多候选评分

一条或多条规则同时命中多个控件时，AutoSkip 不会直接放弃，而是综合以下因素排序：

- 精确文字匹配的分数高于包含和正则匹配；
- View ID、文字和内容描述等特征具有不同权重；
- 明确配置的区域优先于宽泛的全屏匹配；
- 可直接点击或存在可点击父控件的候选优先；
- 面积较小、接近常见跳过按钮位置的控件通常获得更高分；
- 面积过大的控件会被降权。

评分只是在多个匹配项中选择更可信的候选，不能替代准确规则。对容易误触的应用，仍应优先使用专属规则和严格模式。

## 工作原理

一次自动跳过大致经过以下流程：

1. **界面监听**：获得 Shizuku 授权后，AutoSkip 在特权进程中创建 `UiAutomation`，监听窗口和内容变化。
2. **应用范围过滤**：根据总开关、普通/严格模式、白名单和黑名单判断当前应用是否允许执行。
3. **元素采集**：遍历当前窗口中可见且不可编辑的节点，读取文字、内容描述、View ID、控件类型、边界和可点击状态。
4. **规则匹配与评分**：使用当前应用启用的专属规则；没有专属规则或专属规则被停用时使用全局规则。多个候选按匹配质量、位置、大小和可点击性评分。
5. **延迟与复核**：等待规则设置的延迟后重新查找候选，避免点击已经消失或发生变化的控件。对于不可点击的虚拟节点，系统会自动增加短暂准备时间。
6. **动作执行**：优先调用控件点击；必要时尝试可点击父控件或向控件中心注入坐标点击。
7. **结果确认与重试**：点击后继续检查候选和页面状态。若目标仍存在，通常每 200 ms 复核并按需重试，最多 20 次或 4 秒；控件消失、页面/窗口切换或应用切换后立即停止。
8. **记录结果**：只有确认成功的跳过动作才会计入最近动作和统计，单轮重试不会重复累计。

整个过程在设备本地完成。AutoSkip 不修改目标应用，也不分析或拦截其网络流量。

## 隐私与权限

AutoSkip 当前声明的 Android 权限包括：

- `QUERY_ALL_PACKAGES`：列出可启动应用，供应用范围搜索、白名单和黑名单配置使用。
- `RECEIVE_BOOT_COMPLETED`：在启用开机自动恢复后接收设备启动事件。

识别规则、应用范围设置和跳过记录保存在本机。应用本身未声明 `INTERNET` 权限；下载、反馈和捐赠等外部链接由系统浏览器或对应应用打开。AutoSkip 会通过 Shizuku 获得高于普通应用的系统能力，请只安装可信构建并谨慎配置自动点击规则。

## 已知限制与排查

### Shizuku 或 AutoSkip 无法启动

1. 打开 Shizuku，确认首页显示正在运行。
2. 在 Shizuku 的授权管理中确认 AutoSkip 已获允许。
3. 返回 AutoSkip，按首次检查清单中的“修复”或“启动自动跳过”操作。
4. 若 Shizuku 经常停止，请按官方指南允许其后台运行，并检查开发者选项和调试状态。

### 能看到广告，但始终识别不到按钮

1. 确认目标应用未被加入黑名单；严格模式下还要确认其开关已开启。
2. 检查该应用是否启用了专属规则。专属规则会覆盖全局规则。
3. 为实际按钮文案新增规则，或使用学习模式采集 View ID、内容描述和位置。
4. 若按钮绘制在 Canvas、视频、部分 WebView 或安全窗口中，Android 可能没有向 `UiAutomation` 暴露可识别节点，此时无法保证自动跳过。

### 已经匹配，但点击偏慢或没有生效

- 检查规则延迟是否设置过大。
- 对可直接点击的真实控件优先使用“自动”或“仅控件点击”。
- 对只暴露位置的虚拟控件可尝试“自动”或“仅坐标点击”；AutoSkip 会在有限时间内重新确认并重试，不会无限连点。
- 如果广告本身在倒计时结束前拒绝点击，自动重试也不能绕过目标应用的限制。

### 出现误触

1. 在首页最近动作中点击“误触，加入黑名单”，先停止该应用继续触发。
2. 将应用范围改为严格模式，只启用确实需要的应用。
3. 把包含匹配改成精确匹配，或使用更稳定的 View ID。
4. 将全屏区域缩小到按钮实际出现的区域，并避免只按通用控件类型匹配。

### 专属规则不见了

点击“改用全局规则”不会删除专属规则，只会暂时停用。重新进入该应用的“识别规则”，点击“启用专属规则”即可恢复。

### Android 6.0 上的兼容性

受系统限制，Android 6.0 中 AutoSkip 的运行可能与其他无障碍服务冲突：AutoSkip 服务启动后，其他无障碍服务可能停止；停止 AutoSkip 后才会恢复。请在该系统版本上谨慎使用并自行确认兼容性。

## 自行构建

### 构建环境

- JDK 11
- Android SDK 30
- Android Studio，或仓库自带的 Gradle Wrapper

项目使用 Kotlin、Groovy Gradle 和 Java 8 字节码目标。除非正在处理构建迁移，不建议顺手升级 Gradle、Android Gradle Plugin、Kotlin、SDK 或依赖版本。

### 1. 准备本地常量

创建未跟踪文件：

`app/src/main/java/top/xjunz/automator/Constants.kt`

```kotlin
package top.xjunz.automator

const val ALIPAY_DONATE_URL = "xxx"
const val EMAIL_ADDRESS = "xxx"
const val APP_DOWNLOAD_URL = "xxx"
```

该文件已被 `app/.gitignore` 忽略。请按自己的构建用途填写，且不要提交真实联系信息或其他敏感内容。

### 2. 可选：配置自定义签名

未提供 `sign.properties` 时，项目会回退到默认 debug 签名。需要自定义签名时，在项目根目录创建被忽略的 `sign.properties`：

```properties
keystore.file=C:/path/to/android.keystore
keystore.password=xxx
keystore.alias=xxx
keystore.keyPassword=xxx
```

不要提交密钥库、密码或真实签名配置。

### 3. 构建与测试

项目根目录提供两个可直接双击的脚本：

- [一键构建.bat](一键构建.bat)：调用仓库自带的 Gradle Wrapper 生成 Debug APK，并在构建结束后自动还原 `custom.properties`，避免本地构建产生无关版本计数改动。
- [一键安装到手机.bat](一键安装到手机.bat)：自动寻找 `adb`、检查唯一已授权设备，然后使用 `adb install -r` 将现有 Debug APK 正常覆盖安装到手机。脚本不会使用临时安装，也不会在失败时自动卸载旧版本。

安装脚本不会重复构建；如果 APK 尚未生成，请先运行“一键构建.bat”。
如需只检查设备和 APK 是否就绪，可在终端执行 `一键安装到手机.bat --check`，该模式不会安装应用。

也可以在终端中手动执行以下命令。

Windows PowerShell：

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest
```

连接设备后可运行：

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

Linux 或 macOS 请将 `.\gradlew.bat` 替换为 `./gradlew`。Debug APK 通常生成在 `app/build/outputs/apk/debug/`。

> [!WARNING]
> Gradle 配置会在每次构建时递增 `custom.properties` 中的 `build.refine`。普通功能开发或文档修改完成后，应检查并还原非预期的版本计数变化。

编译和自动化测试无法证明真机上的 Shizuku 授权、服务常驻、开机恢复、界面识别和模拟点击一定正常。相关改动仍需在真实设备上验收。

## 项目结构

```text
AutoSkip/
├─ app/                       Android 应用界面、配置、统计、测试与开机恢复
│  └─ src/main/res/raw/       内置默认识别规则
├─ automator/                 Shizuku 特权服务、UiAutomation、规则引擎与记录
│  └─ hidden-apis/            仅供编译使用的 Android 隐藏 API 声明
├─ gradle/wrapper/            Gradle Wrapper
└─ .github/workflows/         Android CI 配置
```

修改 AIDL、Parcelable 或 Binder 方法时，需要同步检查接口声明、服务实现、客户端调用和混淆规则。修改识别或点击逻辑时，建议覆盖候选文字、节点可见性、横竖屏位置与尺寸、可点击父节点、输入事件回退和重复计数等场景。
