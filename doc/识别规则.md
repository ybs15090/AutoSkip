# AutoSkip 识别规则

[返回项目首页](../README.md) · [使用指南](使用指南.md) · [点击与失败重试逻辑](点击与失败重试逻辑.md) · [故障排查](故障排查.md)

识别规则决定 AutoSkip 要寻找什么控件。应用范围决定在哪些应用中工作，两者相互独立；某个应用启用专属规则后，专属规则会替代全局规则。

## 规则字段

| 字段 | 可选项 | 说明 |
| --- | --- | --- |
| 识别特征 | 文本、内容描述、View ID、控件类型 | 对应节点的 `text`、`contentDescription`、资源 ID 和类名 |
| 匹配方式 | 精确、包含、正则 | 精确最稳妥；包含适合附带倒计时的文字；正则最灵活但误匹配风险也最高 |
| 忽略大小写 | 开、关 | 主要影响英文字母，例如同时匹配 `Skip` 和 `SKIP` |
| 控件区域 | 任意、上下半屏、左右半屏、四角 | 限制候选出现的位置，减少同名控件误触 |
| 延迟 | 0～15000 ms | 匹配后至少等待该时长，再重新获取候选并执行点击 |
| 点击方式 | 自动、仅控件点击、仅坐标点击 | 自动模式依次尝试节点、可点击父节点和坐标回退 |

保存时，规则文字会去除首尾空白；延迟会限制在 0～15000 ms。空表达式和被停用的规则不会参与识别。

## 内置默认规则

当前内置四条全局规则，区域均为全屏，延迟均为 0，点击方式均为自动：

| 规则 ID | 特征 | 匹配 | 表达式 |
| --- | --- | --- | --- |
| `default_text_skip_zh` | 文本 | 包含 | `跳过` |
| `default_text_skip_en` | 文本 | 包含、忽略大小写 | `skip` |
| `default_description_skip_zh` | 内容描述 | 包含 | `跳过` |
| `default_description_skip_en` | 内容描述 | 包含、忽略大小写 | `skip` |

“恢复默认”会重新加载内置规则。用户自行新增的“关闭”“略过”“Skip Ad”等规则不属于上述默认集合。

## 如何选择匹配方式

- 按钮始终是固定文字，例如“关闭广告”：优先选择**精确匹配**。
- 按钮附带其他内容，例如“跳过 3”：可以选择**包含匹配**并填写“跳过”。
- 倒计时形式变化，例如“5 秒后关闭”“4 秒后关闭”：可以使用正则，例如 `\d+\s*秒后关闭`。
- 文字为空但资源 ID 稳定：选择 **View ID**，通常比宽泛文字可靠。
- 只能按控件类型匹配：必须同时收紧应用范围和区域，因为通用类型很容易误触。

正则使用 Kotlin/Java 正则语法。无效表达式不会参与识别；合法但过于宽泛的表达式仍可能匹配普通页面元素。

## 全局规则与专属规则

AutoSkip 按以下顺序选择规则集合：

1. 目标应用存在已启用的专属规则：只使用专属规则。
2. 没有专属规则，或专属规则被“改用全局规则”暂时停用：使用全局规则。
3. 被选中的集合中，停用、空表达式或无效正则会被忽略。

因此，创建专属规则后如果发现原有“跳过”不再匹配，应先检查专属规则是否完整；全局规则不会与启用中的专属规则自动合并。

## 仅在启动时跳过

在“应用范围”中找到目标应用，进入“识别规则”详情页，即可设置“仅在启动时跳过”。该开关按应用保存，默认关闭；无论该应用使用全局规则还是专属规则，都会受到这一限制。删除或停用专属规则不会清除该开关。

开启后，应用从其他应用或桌面进入前台时，只在最初 **8 秒**内允许自动点击；一旦确认跳过成功，就结束本轮识别。应用内的页面切换、弹窗和内容更新不会延长或重新开启这段时间。超过窗口的延迟点击和重试会停止，已经执行的点击仍可完成结果确认。

这里的“启动”按应用进入前台判断，包含从后台返回，不能区分进程冷启动与热启动。键盘和系统浮层不会作为新的前台应用重新计时。服务刚启动时已经打开的应用不会获得启动窗口；需要切换到其他应用或桌面，再重新进入。

广告加载或规则延迟超过这 8 秒时，会放弃自动点击。此限制可以减少使用过程中的误触，但启动窗口内仍需准确设置关键词、区域或 View ID。学习模式只采集候选，不受此点击限制影响。

## 候选搜索策略

识别引擎使用两级搜索：

1. 对文字和内容描述中的非正则表达式生成去重关键词，优先调用 Android 平台文本索引查询。对于深层或虚拟 WebView 节点，这通常比手动遍历更快。
2. 如果规则集合还包含内容描述、View ID、控件类型或正则等无法由平台文本查询完整覆盖的特征，则继续遍历活动窗口树。

完整树遍历具有明确预算：最多访问 400 个节点，最大深度 40。节点必须对用户可见、不可编辑且边界非空，才会进入规则匹配与评分。

新应用进入前台、首次事件尚未找到候选时，还会启动短时主动发现。它只轮换查询已有的文字类关键词，不持续遍历整棵树；详细过程见[《点击与失败重试逻辑》](点击与失败重试逻辑.md)。

## 多候选评分

一条或多条规则同时命中多个节点时，AutoSkip 会综合评分，而不是因为候选数量大于 1 就直接放弃。

主要排序因素包括：

- 精确匹配高于包含匹配，包含匹配高于正则匹配；
- View ID、文字和内容描述具有不同的基础权重；
- 明确配置区域会获得额外权重；
- 可直接点击的节点优先，其次是存在可点击父节点的节点；
- 小面积控件通常优于覆盖大块页面的节点；
- 未配置区域时，靠近常见跳过按钮位置，尤其是右上区域的节点更有优势；
- 总分相同时，依次偏向可直接点击、面积更小、离右上角更近的节点。

评分只负责在已经符合规则的候选中排序，不能代替准确的规则。对于容易误触的应用，应优先使用专属规则、精确匹配、稳定 View ID 和更小区域。

## 规则示例

### 固定中文按钮

```text
特征：文本
匹配：精确
表达式：关闭广告
区域：右上
延迟：0
点击：自动
```

### 英文按钮

```text
特征：文本
匹配：包含
表达式：skip
忽略大小写：开启
区域：右上
延迟：0
点击：自动
```

### 带倒计时的按钮

```text
特征：文本
匹配：正则
表达式：\d+\s*秒后跳过
区域：右上
延迟：0
点击：自动
```

如果目标应用在倒计时结束前拒绝点击，即使规则提前匹配，应用仍可能不响应。此时应使用规则延迟，或者等待按钮进入真正可点击状态，而不是无限增加重试次数。

## 降低误触的建议

1. 优先使用严格模式，只开启确认需要处理的应用。
2. 固定文案优先精确匹配，不要默认使用宽泛正则。
3. 有稳定 View ID 时优先使用 View ID。
4. 将区域限制到按钮实际出现的位置。
5. 使用学习模式查看候选边界和可点击状态。
6. 发生误触后先把应用加入黑名单，再调整规则。
