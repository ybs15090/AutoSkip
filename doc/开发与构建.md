# AutoSkip 开发与构建

[返回项目首页](../README.md) · [识别规则](识别规则.md) · [点击与失败重试逻辑](点击与失败重试逻辑.md) · [故障排查](故障排查.md)

本文说明当前仓库的开发环境、模块边界、本地常量、签名、构建测试、CI 发布和真机验收要求。除非任务明确要求迁移，不要顺手升级 Gradle、Android Gradle Plugin、Kotlin、SDK 或依赖版本。

## 固定开发环境

| 项目 | 当前配置 |
| --- | --- |
| 构建脚本 | Groovy Gradle |
| Gradle Wrapper | 7.3.3 |
| Android Gradle Plugin | 7.2.0 |
| Kotlin | 1.5.30 |
| 本地 Gradle JDK | JDK 11 |
| `compileSdk` / `targetSdk` | 30 / 30 |
| `minSdk` | 23（Android 6.0） |
| Java/Kotlin 字节码目标 | Java 8 / JVM 1.8 |

CI 为兼容较新的 Android SDK 工具，先使用 JDK 17 安装 SDK，再切换到 JDK 11 执行本项目 Gradle 任务。本地构建 Gradle 时仍应使用 JDK 11。

## 项目结构

```text
AutoSkip/
├─ app/                         Android 界面、配置、统计、备份恢复、测试和开机恢复
│  ├─ src/main/res/raw/         内置默认识别规则
│  └─ screenshots/              README 使用的界面截图
├─ automator/                   Shizuku 特权服务、UiAutomation 和规则引擎
│  └─ hidden-apis/              仅供编译使用的 Android 隐藏 API 声明
├─ doc/                         使用、规则、点击、隐私、排障和开发文档
├─ gradle/wrapper/              Gradle Wrapper
├─ .github/workflows/           Android CI 与 Release 发布
├─ 一键构建.bat                 Windows Debug 构建脚本
└─ 一键安装到手机.bat           Windows ADB 覆盖安装脚本
```

`automator/hidden-apis/` 只是编译期声明，不应当作普通运行时实现。修改隐藏 API、`UiAutomation`、输入注入或 Shizuku 服务绑定时，必须考虑 API 23 及不同厂商系统的兼容分支。

## 准备本地常量

应用模块依赖未跟踪文件：

`app/src/main/java/top/xjunz/automator/Constants.kt`

```kotlin
package top.xjunz.automator

const val ALIPAY_DONATE_URL = "xxx"
const val EMAIL_ADDRESS = "xxx"
const val APP_DOWNLOAD_URL = "xxx"
```

该文件已被忽略。请根据自己的构建用途填写，但不要提交真实联系信息、内部下载地址或其他敏感内容。

## 签名配置

没有 `sign.properties` 时，`sign.gradle` 会回退到默认 debug 签名。需要使用自定义签名时，在项目根目录创建被忽略的 `sign.properties`：

```properties
keystore.file=C:/path/to/android.keystore
keystore.password=xxx
keystore.alias=xxx
keystore.keyPassword=xxx
```

密钥库、密码、真实别名和签名配置不得提交到仓库。使用不同签名构建的 APK 通常不能直接覆盖安装；切换签名前应先备份重要规则和记录，并明确卸载旧版会带来的数据影响。

## Windows 一键脚本

- [一键构建.bat](../一键构建.bat)：调用仓库 Wrapper 构建 Debug APK，并在结束后恢复构建前的 `custom.properties`，避免普通本地构建混入版本计数变化。
- [一键安装到手机.bat](../一键安装到手机.bat)：查找 `adb`、要求恰好一个已授权设备，再用 `adb install -r` 覆盖安装已有 Debug APK；不会自动卸载旧版，也不会自动重新构建。

推荐顺序：先运行构建脚本，确认 APK 已生成，再运行安装脚本。只检查设备与 APK 是否就绪时可执行：

```powershell
.\一键安装到手机.bat --check
```

该检查模式不会安装应用。

## 手动构建与测试

Windows PowerShell：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

Linux 或 macOS：

```bash
./gradlew testDebugUnitTest assembleDebug
```

Debug APK 生成在：

```text
app/build/outputs/apk/debug/
```

连接设备后，可运行设备测试：

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

或手动覆盖安装指定 APK：

```powershell
adb devices
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

实际文件名以输出目录为准。如果设备显示 `unauthorized`，应先在手机上确认 USB 调试授权；存在多台设备时，用 `adb -s <serial>` 明确选择，避免装到错误设备。

> [!WARNING]
> Gradle 配置会在每次构建配置阶段递增 `custom.properties` 中的 `build.refine`。手动构建后必须执行 `git diff -- custom.properties` 检查。若变化仅来自普通测试构建，应把它排除在功能提交之外；发布版本或确需更新版本标识时再有意识地保留。

## 测试范围

JVM 单元测试放在各模块的 `src/test/`，设备测试放在 `src/androidTest/`。识别和点击逻辑至少应覆盖：

- 文字、内容描述、View ID、控件类型与正则候选；
- 节点可见性、可编辑性和空边界过滤；
- 横竖屏位置、区域和尺寸；
- 多候选评分与同名候选指纹；
- 当前节点、可点击父节点和坐标回退；
- 零延迟与非零延迟路径；
- 点击后 `PRESENT`、`GONE`、`UNKNOWN` 三种复核状态；
- 重试次数、时间预算和一次成功只计数一次；
- 新前台会话主动发现的启动与停止条件。

点击状态机和当前时序参数见[《点击与失败重试逻辑》](点击与失败重试逻辑.md)。

数据备份使用版本化的 UTF-8 JSON。修改备份模型时，应继续保证旧格式可明确识别，未知格式版本必须拒绝而不是按空配置导入。相关测试或人工检查至少应覆盖：必选配置、可选统计、未安装应用包名、损坏字段、未知枚举、非法正则、超大文件、停服前后两次状态检查、写入失败回滚，以及“不含统计时保留本机统计”。格式和产品行为见[《数据备份与恢复》](数据备份与恢复.md)。

编译和 JVM 测试不能证明以下真机行为正常：

- Shizuku/Sui 授权与 Binder 生命周期；
- 服务常驻和开机自动恢复；
- 厂商系统上的活动窗口与节点获取；
- WebView 发布虚拟节点的时机；
- 节点动作、父节点动作和输入注入；
- 首次冷启动广告的实际跳过速度。

涉及这些代码时，应记录手机型号、Android/API 版本、Shizuku/Sui 版本、目标应用版本和人工复现步骤，并至少测试服务重启后的首次启动与连续多次启动。

## CI 与 Release

`.github/workflows/android.yml` 当前执行：

- 向 `master` 推送、针对 `master` 的 Pull Request 或手动触发：运行 `testDebugUnitTest assembleDebug`，上传 Debug APK，artifact 保留 14 天。
- 推送 `vMAJOR.MINOR.PATCH` 标签：验证语义版本格式，把标签转换为 Android `versionName` 和 `versionCode`，使用 GitHub Secrets 中的签名材料构建 Release APK，并发布到 GitHub Releases。

Release 任务要求以下 Secrets：

- `KEYSTORE_BASE64`
- `KEYSTORE_ALIAS`
- `KEYSTORE_PASSWORD`
- `KEYSTORE_KEY_PASSWORD`

标签必须形如 `v1.2.3`。CI 会拒绝格式错误、超出映射范围或缺少签名 Secrets 的发布，不应为了绕过检查而把签名材料写入工作流或仓库。

## 修改与交付检查

修改 AIDL、Parcelable 模型或 Binder 方法时，同步核对：

1. `.aidl` 声明；
2. Kotlin 服务实现；
3. 应用端调用；
4. 混淆规则；
5. 真机跨进程行为。

提交前至少执行与改动对应的最小测试，并检查：

```powershell
git diff --check
git status --short
git diff -- custom.properties
```

保留用户已有的未提交修改。暂存时显式指定本次文件，不使用 `git add .` 或 `git add -A`，也不要提交构建产物、本地 SDK 路径、密钥库、密码或未跟踪常量。
